# 后台鉴权

后台页面 `/admin` 及其子页面先调用 `GET /api/admin/session`，服务端确认当前账号具有 `ADMIN` 角色后才显示后台内容。浏览器保存的 `user.role` 只用于界面展示，不能作为权限依据。

管理接口由 Spring Security 和控制器权限注解共同保护，包括图片上传、产品和文章管理、订单状态、用户管理、联系消息管理、访问统计及站点设置。公开内容只允许读取；注册始终创建普通用户，个人资料更新不能修改角色。

- 未登录、JWT 无效或过期、账号已禁用或删除：返回 `401`。
- 有效普通用户访问管理接口：返回 `403`。
- 每次请求从数据库读取最新角色和账号状态，撤销管理员角色后旧 JWT 不能继续访问管理接口。
- JWT 和密码不会由管理员身份校验接口返回；用户实体也不会序列化密码哈希。

## JWT 签名密钥

通过后端环境变量 `APP_JWT_SECRET` 配置私有的随机密钥，至少 32 个 UTF-8 字节。不要使用仓库中曾经公开的密钥，也不要提交真实密钥到代码仓库。

未配置时，后端每次启动生成新的随机密钥，旧登录凭证会在重启后失效。需要重启后保持登录或部署多个后端实例时，应为所有实例配置同一份持久密钥。更换签名密钥后，所有用户都需要重新登录。

本次权限改动不会修改数据库中已有账号的密码。`DataInitializer` 中的默认账号仍用于课程演示；公开部署前应改掉演示管理员密码。

## 验证

在 `backend` 目录运行 `mvn test`。权限回归测试使用独立 H2 内存数据库，覆盖访客、普通用户、管理员、无效/过期/伪造凭证、禁用账号和角色撤销，不依赖或修改生产 MySQL 数据。

前端使用 `pnpm build` 验证构建。进入后台时权限请求失败会停止显示后台内容，用户可以重试；登录失效只清理登录信息，保留购物车。
